# 1. Tokens in LLMs

## Definition
A token is a unit of text processed by a Large Language Model (LLM). It can be a word, part of a word, number, punctuation mark, or symbol.

## Tokenization
Tokenization is the process of splitting text into smaller units called tokens.

**Example:**
```text
Input: I love AI.

Possible tokens:
["I", " love", " AI", "."]

Token count: 4
```

*Note: Actual tokenization depends on the model's tokenizer.*

## How Tokens Work
1. User provides text input.
2. Tokenizer converts text into tokens.
3. Tokens are mapped to numerical token IDs.
4. The model processes the input and generates output tokens.
5. Output tokens are decoded into readable text.

## Types of Tokens in API Usage

- **Input Tokens:** Tokens provided to the model as input.
- **Output Tokens:** Tokens generated by the model in its response.

## Why Are Tokens Important?
- **API Cost:** Many LLM APIs charge based on input and output token usage.
- **Context Limits:** Models can process only a limited amount of context.
- **Response Length:** Longer responses generally consume more output tokens.
- **Performance:** Token usage can affect processing time and efficiency.

## Important Points
- One word does not always equal one token.
- Different models may use different tokenizers.
- Token IDs are numerical identifiers, not the final text itself.
- Token limits and API pricing depend on the model.

## Interview Question

**Q. What is a token in an LLM?**

A token is a unit of text that an LLM processes. It can represent a complete word, part of a word, or a punctuation mark. Text is tokenized and mapped to numerical IDs before being processed by the model.

# 2. Context Window in LLMs

## Definition
A context window is the maximum amount of information, measured in tokens, that an LLM can process or consider in a single request.

## Example

Suppose a model has a context window of 8,000 tokens.

- System instructions: 500 tokens
- User question: 500 tokens
- Document: 6,000 tokens
- Total input: 7,000 tokens

The remaining capacity is theoretically 1,000 tokens, subject to the model's input/output limits and API rules.

## What Happens When the Limit Is Exceeded?
- The API may reject the request.
- The application may split the input into smaller chunks.
- The application may summarize or remove less relevant information.

## Context Window vs Memory

| Context Window | Memory |
|---|---|
| Information available in a model request | Information retained or retrieved across interactions |
| Has a finite token capacity | Depends on the system's design |
| Includes current instructions and available conversation context | May provide information from earlier interactions |

## Techniques for Managing Long Contexts

1. **Chunking:** Divide large documents into smaller parts.
2. **Summarization:** Condense lengthy information.
3. **Retrieval:** Fetch information relevant to the user's query.
4. **Context Management:** Prioritize important information.

## Important Points
- Context window capacity is measured in tokens.
- Input and output limits depend on the model and API.
- A context window is not the same as persistent memory.
- Larger documents may require chunking or retrieval.

## Interview Question

**Q. What is a context window in an LLM?**

A context window is the maximum amount of information an LLM can consider in a single request, measured in tokens. If the input exceeds the available limit, the API may reject it or the application may need to shorten, summarize, or split the input.

# 3. Temperature in LLMs

## Definition
Temperature is a parameter that controls the randomness of token selection during LLM text generation.

## Low vs High Temperature

| Low Temperature | High Temperature |
|---|---|
| More predictable outputs | More varied outputs |
| Generally lower randomness | Generally higher randomness |
| Useful for consistent tasks | Useful for creative tasks |

## Example

**Prompt:** Suggest a name for an AI assistant.

- Low temperature: AI Assistant
- High temperature: NovaMind

These are illustrative examples, not guaranteed outputs.

## Typical Use Cases

- **Data Extraction:** Lower temperature for more predictable responses.
- **Classification:** Lower temperature as a reasonable starting point.
- **Creative Writing:** Higher temperature to explore varied outputs.
- **Brainstorming:** Higher temperature to generate diverse ideas.

## Example Python Configuration

```python
temperature = 0
```

A low value generally makes outputs more predictable.

```python
temperature = 1.0
```

A higher value relative to zero generally allows more variation.

*Note: Supported ranges and behavior depend on the model and API.*

## Important Points
- Temperature affects token selection during generation.
- Higher temperature does not guarantee better creativity or accuracy.
- Temperature 0 does not guarantee perfect determinism across all systems.
- Structured output also requires appropriate instructions, schemas, or validation.

## Interview Question

**Q. What is temperature in an LLM?**

Temperature controls the randomness of token selection during text generation. Lower values generally produce more predictable responses, while higher values can produce more varied responses. Lower temperatures are often useful for structured tasks, while higher temperatures can help with creative tasks.


# 4. Embeddings

## Definition
An embedding is a numerical representation of data, such as text, designed to capture meaningful relationships between items.

An embedding is generally represented as a vector of numbers.

## Example

Two sentences:

- "I love dogs."
- "I like puppies."

An embedding model may represent these sentences as nearby vectors because their meanings are similar.

*Note: Example vectors are illustrative.*

## Why Are Embeddings Important?
Embeddings help applications compare the meaning of text rather than relying only on exact keyword matches.

## How Embeddings Work

1. Provide text to an embedding model.
2. The model converts the text into a numerical vector.
3. Store the vector if needed.
4. Compare vectors using a similarity measure.
5. Retrieve or group relevant content.

## Semantic Similarity
Semantic similarity measures how closely two pieces of text relate in meaning.

Example:

- "Buy an automobile."
- "Purchase a car."

These sentences use different words but have similar meanings.

## Cosine Similarity
Cosine similarity measures the cosine of the angle between two vectors.

- Close to 1: Similar vector directions.
- Close to 0: Approximately perpendicular vectors.
- Close to -1: Opposite vector directions.

Interpretation depends on the embedding model and application.

## Applications
- Semantic Search
- Retrieval-Augmented Generation (RAG)
- Recommendation Systems
- Document Clustering
- Machine Learning Classification

## Interview Question

**Q. What are embeddings in AI?**

Embeddings are numerical vectors that represent data such as text. They help AI applications identify relationships between items based on their representations. They are commonly used in semantic search, RAG systems, recommendations, and clustering.

# 1. Prompt Engineering

## What Is Prompt Engineering?

Prompt engineering is the process of designing and improving instructions given to an LLM to obtain useful, relevant, and reliable responses.

A prompt can contain instructions, context, input data, examples, and output requirements.

## Components of a Good Prompt

- **Role:** Defines the role the model should perform.
- **Instruction:** Explains what the model must do.
- **Context:** Provides relevant background information.
- **Input:** Contains the data to process.
- **Constraints:** Defines rules and limitations.
- **Output Format:** Specifies how the response should be returned.

## Example: Poor Prompt vs Good Prompt

**Poor Prompt:**

```text
Analyze this customer application.
```

Problem: The task and expected output are unclear.

**Good Prompt:**

```text
Analyze the customer application below.

Extract the following fields:
- customer_name
- age
- city

Return the result as JSON.

If a field is missing, return null.
Do not invent information.

Application:
{{customer_application}}
```

The second prompt specifies the task, required fields, output format, and missing-data behavior.

## Common Prompting Techniques

| Technique | Meaning | Use Case |
|---|---|---|
| Zero-shot | Give instructions without examples | Simple classification |
| Few-shot | Provide a few input-output examples | Consistent formatting |
| Role prompting | Assign a role to the model | Domain-specific tasks |
| Step-by-step prompting | Request intermediate reasoning or a structured solution process | Complex problem-solving |
| Constraint-based prompting | Specify strict rules | Data extraction |

## Best Practices

- Use clear and specific instructions.
- Separate instructions from input data.
- Provide examples when useful.
- Specify the expected output format.
- Define how missing or ambiguous information should be handled.
- Test prompts on multiple examples.
- Do not assume a better prompt guarantees factual correctness.

## Interview Question

**Q. What is prompt engineering?**

Prompt engineering is the process of designing and refining instructions to guide an LLM toward useful outputs. It involves specifying the task, context, constraints, examples, and expected output format.

# 2. Structured Outputs

## What Are Structured Outputs?

Structured outputs are responses generated in a predefined format, such as JSON, that follow an expected structure.

They are useful when an AI response must be processed by another program.

## Free-Form Text vs Structured Output

**Free-form text:**

```text
The customer is Aisha, age 25, from Delhi.
```

**Structured output:**

```json
{
  "customer_name": "Aisha",
  "age": 25,
  "city": "Delhi"
}
```

The JSON format makes individual fields easier to access programmatically.

## JSON Fundamentals

JSON supports these basic data types:

| Type | Example |
|---|---|
| String | `"Aisha"` |
| Number | `25` |
| Boolean | `true` |
| Null | `null` |
| Array | `["Delhi", "Mumbai"]` |
| Object | `{"city": "Delhi"}` |

Important rules:

- Strings and object keys use double quotes.
- Numbers do not require quotes.
- `null`, `true`, and `false` are lowercase.
- JSON does not allow trailing commas.
- Valid JSON does not automatically mean the data is correct.

## JSON Mode vs Schema-Constrained Output

**JSON mode:** Requests output in valid JSON format.

**Schema-constrained output:** Requires the response to follow a defined structure, such as required fields and expected data types, where supported by the API.

Example schema requirements:

```json
{
  "customer_name": "string",
  "age": "integer",
  "city": "string or null"
}
```

This is an illustrative schema description, not a formal JSON Schema document.

## Python JSON Validation

```python
import json

response = '{"customer_name": "Aisha", "age": 25}'

try:
    data = json.loads(response)
    print(data["customer_name"])
except json.JSONDecodeError:
    print("Invalid JSON")
```

`json.loads()` parses a JSON string into a Python object. It raises `JSONDecodeError` if the string is invalid JSON.

For real applications, also validate required fields, types, and business rules.

## Important Points

- Structured output improves consistency and programmatic usability.
- JSON syntax validation checks whether the response is valid JSON.
- Schema validation checks whether the response follows the expected structure.
- Business validation checks whether the values make sense.
- Structured output does not guarantee factual accuracy.

## Interview Question

**Q. Why are structured outputs important in LLM applications?**

Structured outputs allow applications to receive information in a predictable format, such as JSON. This makes it easier to validate data, access individual fields, and integrate LLM responses with APIs and databases.

# 3. LLM APIs

## What Is an API?

An API (Application Programming Interface) allows two software systems to communicate with each other through defined rules.

An LLM API lets an application send input to a language model and receive its response.

## How an LLM API Works

```text
Python Application
        |
        v
Prepare Input and Instructions
        |
        v
Send API Request
        |
        v
LLM Processes the Request
        |
        v
Receive Model Response
        |
        v
Validate and Use the Response
```

## Important API Concepts

- **API Key:** A credential used to authenticate requests.
- **Request:** Data sent to the API.
- **Response:** Data returned by the API.
- **Model:** The LLM selected to process the request.
- **Parameters:** Settings such as temperature and output limits.
- **Rate Limit:** Restriction on request frequency or usage.
- **Error Handling:** Managing failed requests safely.

## Python Example

The following example uses the OpenAI Python SDK and the Responses API. It assumes the SDK is installed and the API key is configured in the environment.

Install the SDK:

```bash
pip install openai
```

Set the `OPENAI_API_KEY` environment variable before running the program.

```python
from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="YOUR_SUPPORTED_MODEL",
    input="Explain artificial intelligence in one sentence."
)

print(response.output_text)
```

Replace `YOUR_SUPPORTED_MODEL` with a model currently supported by your API account.

## Secure API Key Handling

Never hardcode API keys in source code or commit them to GitHub.

Use environment variables or an appropriate secrets manager.

```python
import os

api_key = os.getenv("OPENAI_API_KEY")

if not api_key:
    raise ValueError("API key is not configured")
```

The SDK can read `OPENAI_API_KEY` from the environment automatically.

## Error Handling

Common API problems include:

- Invalid API key
- Insufficient quota or billing issues
- Rate limits
- Unsupported model
- Network failures
- Invalid request parameters

Applications should handle errors, use bounded retries where appropriate, and avoid exposing secrets in logs.

## Interview Question

**Q. How does an LLM API work?**

An application sends a request containing input and model settings to an LLM API. The service processes the request and returns a response, which the application can validate and use.

# 4. Hallucinations

## What Is an LLM Hallucination?

A hallucination occurs when an LLM generates information that is false, unsupported, or inconsistent with the available evidence.

A response can sound confident and fluent while still being incorrect.

## Why Do Hallucinations Occur?

- The model may lack relevant information.
- The prompt may be ambiguous.
- The provided context may be incomplete.
- The model may generate plausible but unsupported details.
- The question may ask for information the model cannot reliably determine.

## Example

**Prompt:**

```text
Who won a fictional tournament called the
Global AI Cup 1890?
```

**Potential hallucination:**

```text
The tournament was won by Team Alpha.
```

If the model has no reliable evidence for this claim, it should not invent an answer.

A safer instruction is:

```text
Answer only using the supplied evidence.
If the answer is unavailable, state that the
information is not available.
```

This reduces unsupported answers but does not eliminate hallucinations completely.

## How to Reduce Hallucinations

1. Provide reliable source documents.
2. Use Retrieval-Augmented Generation (RAG) when appropriate.
3. Instruct the model not to invent missing information.
4. Require evidence or citations for factual claims where feasible.
5. Validate important claims against trusted sources.
6. Use human review for high-impact decisions.
7. Test the application on questions with missing or conflicting evidence.

## What Is RAG?

Retrieval-Augmented Generation combines information retrieval with LLM response generation.

```text
User Question
      |
      v
Retrieve Relevant Documents
      |
      v
Provide Documents to the LLM
      |
      v
Generate an Evidence-Based Answer
```

RAG can improve grounding in provided documents, but retrieval errors or incorrect reasoning can still produce wrong answers.

## Important Distinction

- **Fluency:** How natural the response sounds.
- **Correctness:** Whether the response is factually accurate.
- **Grounding:** Whether the response is supported by available evidence.

These are different properties.

## Interview Question

**Q. What is an LLM hallucination, and how can it be reduced?**

An LLM hallucination is a false or unsupported response generated by a model. It can be reduced through reliable context, retrieval, evidence checking, validation, and human review. However, no single technique guarantees that hallucinations will never occur.

# 5. Token Costs

## Why Do Tokens Affect Cost?

Many commercial LLM APIs charge according to the number of input and output tokens processed.

Pricing differs by model and may include additional charges for tools, cached tokens, or other features.

## Types of Token Usage

- **Input Tokens:** Tokens supplied to the model.
- **Output Tokens:** Tokens generated by the model.

The prices per million tokens may differ.

## Cost Formula

When pricing is specified per million tokens:

```text
Input Cost =
(Input Tokens / 1,000,000) × Input Price per Million

Output Cost =
(Output Tokens / 1,000,000) × Output Price per Million

Total Cost =
Input Cost + Output Cost
```

This is a simplified calculation. Additional billable features may change the final cost.

## Example Calculation

Assume a hypothetical API has these prices:

- Input: $2 per million tokens
- Output: $8 per million tokens

A request uses:

- Input tokens: 10,000
- Output tokens: 2,000

Calculation:

```text
Input Cost
= (10,000 / 1,000,000) × $2
= $0.02

Output Cost
= (2,000 / 1,000,000) × $8
= $0.016

Total Cost
= $0.036
```

These prices are illustrative, not current pricing for a particular model.

## Estimating Cost for Multiple Requests

Suppose 1,000 requests have the same usage as the example above.

```text
Cost per request = $0.036

Total cost = 1,000 × $0.036
           = $36
```

Actual usage varies with input size, output length, model choice, and application behavior.

## How to Reduce Token Costs

- Remove unnecessary instructions and repeated context.
- Limit output length when appropriate.
- Retrieve only relevant document chunks.
- Use smaller or cheaper models for suitable tasks.
- Cache reusable results when appropriate.
- Monitor actual token usage.
- Evaluate cost alongside response quality.

## Interview Question

**Q. How do you calculate LLM API costs?**

Multiply input token usage by the input price per token and output token usage by the output price per token. Add both costs and include any additional billable features that apply.

# 6. Basic LLM Evaluation

## What Is LLM Evaluation?

LLM evaluation is the process of measuring whether an LLM application produces useful, correct, consistent, and appropriate responses.

A single good response does not prove that an application is reliable.

## Important Evaluation Metrics

| Metric | Meaning |
|---|---|
| Correctness | Is the answer factually correct? |
| Relevance | Does it answer the user's question? |
| Completeness | Does it include the required information? |
| Consistency | Does it behave similarly on equivalent inputs? |
| Format Validity | Does the response follow the required format? |
| Groundedness | Is the answer supported by the supplied evidence? |
| Latency | How long does the response take? |
| Cost | How much does the request cost? |

The appropriate metrics depend on the task.

## Example: Customer Data Extraction

Suppose an application extracts customer information from an application form.

Expected output:

```json
{
  "customer_name": "Aisha",
  "age": 25,
  "city": "Delhi"
}
```

Evaluation checks:

- Is the customer name correct?
- Is age extracted accurately?
- Is the city correct?
- Are missing fields handled correctly?
- Is the response valid JSON?
- Does the output follow the required schema?

A response may be valid JSON but still contain the wrong customer name. Therefore, format validation and correctness evaluation are separate checks.

## Basic Evaluation Workflow

```text
Create a Test Dataset
        |
        v
Define Expected Results
        |
        v
Run the Application
        |
        v
Compare Actual vs Expected Output
        |
        v
Calculate Metrics
        |
        v
Analyze Errors
        |
        v
Improve and Retest
```

## Example Test Dataset

| Input | Expected Result |
|---|---|
| Application with complete details | Extract all fields correctly |
| Application missing age | Return null for age |
| Application with ambiguous city | Avoid unsupported assumptions |
| Invalid or empty input | Handle the error safely |

## Comparing Two Prompts

Suppose Prompt A and Prompt B are designed for customer data extraction.

Test both prompts on the same dataset.

Measure:

- Field-level accuracy
- JSON validity rate
- Schema compliance rate
- Missing-field handling
- Average latency
- Average cost per request

A prompt that produces one perfect answer may still fail on other inputs. Testing multiple representative examples gives stronger evidence of quality.

## Simple Accuracy Formula

For a straightforward classification task:

```text
Accuracy = Correct Predictions / Total Predictions
```

For structured extraction, field-level accuracy can be calculated as:

```text
Field Accuracy =
Correctly Extracted Fields / Total Expected Fields
```

Define the treatment of missing or invalid fields consistently before calculating the metric.

## Interview Question

**Q. How would you evaluate an LLM application?**

I would create a representative test dataset, define expected results, and measure correctness, relevance, format validity, latency, and cost. I would analyze failures, improve the application, and rerun the same tests to verify the improvement.
